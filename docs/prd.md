# 产品需求文档 (PRD)

## 1. 产品一句话

> **ResumeAI**：5 分钟部署一个 AI 简历分身，让面试官和"你"直接对话。

## 2. 给谁用？

| 角色 | 场景 | 痛点 |
|------|------|------|
| **求职者（开发者）** | 找工作时想让自己在简历堆中脱颖而出 | 传统简历千篇一律，无法展示技术深度 |
| **面试官** | 收到候选人链接，想快速了解这个人 | 一张纸不够深入，约面试成本又太高 |
| **开源贡献者** | 觉得项目有意思，想参与开发 | 需要一个结构清晰、好上手的开源项目 |

## 3. 解决什么核心问题？

传统简历是**静态的、单向的**——面试官只能读，不能问。这带来三个问题：

1. **信息衰减**：简历上的每句话面试官都可能想追问，但约面试之前没法追问
2. **技术能力无法证明**：简历写"熟悉 LLM 应用开发"，怎么验证？面试官无法判断真假
3. **差异化困难**：100 份简历里 99 份都写"熟练使用 React"，怎么脱颖而出？

**ResumeAI 的解法**：
- 把简历变成**可对话的 AI 分身**，面试官想问什么直接打字
- 部署和配置的过程本身就是**技术能力的可验证证明**
- 发一个链接比发一份 PDF **酷 100 倍**

## 4. 核心流程

```
求职者（开发者）：
  Fork 仓库 → 编辑 profile.yaml → 填环境变量 → 一键部署到 Vercel → 获得链接 → 发链接给面试官

面试官：
  打开链接 → 看到欢迎语 → 打字提问 → AI 流式回复 → 追问 → 了解更多 → 形成印象
```

## 5. MVP 必须有什么？（P0）

- [x] 多 LLM Provider 支持（OpenAI / DeepSeek / 智谱 / 通义千问 / Moonshot）
- [x] YAML 配置文件驱动（profile.yaml + Zod 校验）
- [x] RAG-lite 引擎（YAML → System Prompt，Token ≤ 4K）
- [x] SSE 流式对话 + Markdown 渲染 + 代码高亮
- [x] Prompt 注入防护 + 超范围拒答
- [x] Vercel 一键部署
- [x] 移动端响应式适配 + 暗色模式
- [x] Live Demo 站点（作者本人的 AI 分身）
- [x] OG 社交分享图片
- [x] 中英双语 README（含技术名片模块 + 简历话术）

## 6. MVP 不做什么？（先砍掉）

| 功能 | 砍掉原因 |
|------|----------|
| 用户注册/登录 | 每人部署自己的实例，天然隔离 |
| AI 对话采集个人资料 | 先验证"面试官愿意对话"这个核心假设，v1.1 再加 |
| 上传 PDF/Word 简历 | 同上 |
| 向量数据库 (ChromaDB) | 增加部署复杂度，违背"5 分钟"承诺 |
| FastAPI 后端 | Next.js Route Handler 够用 |
| 多套视觉模板 | 先做好一套精品模板 |
| 多语言 i18n | v1.0 界面英文，README 中英双语 |
| 自定义域名 | 不是 MVP 阶段的核心需求 |
| 付费功能 | 开源项目，不商业化（至少 v1.0 不） |

## 7. 为何这样设计 MVP？

遵循三个原则：

1. **5 分钟可部署**：任何让部署变复杂的东西，砍掉
2. **面试官体感优先**：所有功能以"面试官对话体验是否爽"为判断标准
3. **代码即营销**：README 的质量和产品代码同等重要

## 8. 未来展望（不承诺）

- **v1.1**：Web 配置界面 → 非技术用户也能用
- **v1.1**：AI 对话辅助填写 profile → "聊 10 分钟生成简历"
- **v1.2**：PDF 上传解析 → 已有简历的快速导入
- **v1.2**：多套模板 → 视觉多样性
- **v2.0**：SaaS 化 → 不需要 Fork 和部署，在线注册即用
